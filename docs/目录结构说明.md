# 目录结构说明

> 划分原则：**按职责划分，而不是按来源划分**。
> 源码、素材、文档、工具各自独立互不嵌套，换电脑拷整个目录就能跑。

## 一、四分区职责

| 目录 | 职责 | 谁产生的 | 入库 |
|:---|:---|:---|:--:|
| `firmware/` | ESP32-S3 固件源码（PlatformIO 工程） | 手写 | ✅ |
| `assets/` | 素材与产物：原始 webm、预览 mp4、动画池、SD 卡镜像 | 人工导入 + 流水线生成 | 部分 |
| `docs/` | 方案、清单、实测报告、调研 | 手写 + 脚本生成 | ✅ |
| `tools/` | ffmpeg 与 PC 端流水线脚本 | 手写 + 下载 | 部分 |

## 二、完整树

```
dshPetDafeiyu/                                  项目根（git 仓库根）
├─ README.md                        总入口：四分区导航 + 换电脑三步跑起来
├─ .gitignore                       大二进制不入库清单
│
├─ firmware/                        ── 固件源码（PlatformIO 工程）──
│  ├─ platformio.ini                环境、依赖、分区表、文件系统类型
│  ├─ partitions.csv                自定义 16MB 分区表：去 OTA，storage 11.9MB
│  ├─ include/                      头文件（接口契约集中在这里）
│  │  ├─ config.h                   屏/内容区/FPS/存储后端/核绑定 等全部常量
│  │  ├─ petpack.h                  ★ .petpack 容器契约
│  │  ├─ storage.h                  ★ Flash / SD 双后端抽象
│  │  ├─ decoder.h                  JPEGDEC → RGB565 写后缓冲
│  │  ├─ display.h                  ★ 双核 + 双缓冲刷屏接口
│  │  ├─ player.h                   帧率调度、循环、丢帧
│  │  ├─ animator.h                 状态机：待机链/点击/拖拽/事件
│  │  └─ input.h                    触摸/按键防抖
│  ├─ src/                          与 include/ 一一对应的实现
│  ├─ data/                         ★ LittleFS 镜像源（烧进 Flash 的动画）
│  │  └─ packs/<分类>/<名>.petpack  阶段 1 的 5 段，约 3.5MB
│  └─ test/                         PlatformIO Unity 单测（预留）
│
├─ assets/                          ── 素材与产物 ──
│  ├─ source-webm/                  输入：106 段 VP9-alpha 原始素材（51.8MB）
│  ├─ preview-mp4/                  106 段 H.264 黑底预览（仅用于快速查看）
│  ├─ animations.json               ★ 动画池与权重（animator 的输入）
│  ├─ 预览.html                     网页画廊（引用 source-webm/，双击可看）
│  └─ sdcard/                       ★ 阶段 2 的 SD 卡镜像根（结构 = 卡根）
│     ├─ packs/<分类>/<名>.petpack  输出：106 个帧包，77.5MB
│     └─ index.json                 每段帧数/体积/平均帧大小
│
├─ docs/                            ── 文档 ──
│  ├─ ESP32桌宠技术方案.md           整体方案：格式选型/硬件/固件/风险
│  ├─ 动画清单.md                    106 段逐段清单与分类权重
│  ├─ 阶段0-实测报告.md              流水线产物统计与抽检结果（report.py 生成）
│  ├─ 调研-同类项目与解码库实测.md     ★ 联网调研：同类项目对比 + 解码库实测
│  ├─ 目录结构说明.md                本文件
│  ├─ calibration.json              三种分辨率的体积实测
│  └─ sample_frame.png / sample_strip.png   抽检样张
│
└─ tools/                           ── 工具 ──
   ├─ ffmpeg/                       完整版 ffmpeg（200MB，download-ffmpeg.mjs 下载）
   └─ pipeline/                     PC 端素材流水线
      ├─ download-ffmpeg.mjs        下载完整版 ffmpeg
      ├─ pipeline.py                webm → JPEG 帧 → .petpack（含回读校验）
      ├─ report.py                  抽样真解码 + 生成 docs/阶段0-实测报告.md
      ├─ pick_flash.py              ★ 从 sdcard 挑 5 段 → firmware/data/packs
      ├─ README.md                  流水线用法与踩坑记录
      └─ build/                     中间 JPEG 帧（跑完即清）
```

## 三、数据流向

```
assets/source-webm/            （输入，51.8MB）
   │  tools/pipeline/pipeline.py
   ▼
assets/sdcard/packs/           （全量产物，77.5MB）
   ├──────────────► 阶段 2：整目录拷进 SD 卡，固件扫 /packs
   │
   │  tools/pipeline/pick_flash.py（精选 5 段）
   ▼
firmware/data/packs/           （阶段 1，约 3.5MB）
   │  pio run -t uploadfs
   ▼
Flash 的 storage 分区（11.9MB，LittleFS）
```

**两个阶段共用同一份 `.petpack` 文件、同一套读取代码**，
差别只在 `storage` 模块返回哪个 `fs::FS&`（LittleFS 还是 SD）。

## 四、什么文件放哪

| 想加东西 | 放哪 |
|:---|:---|
| 新的一段动画（webm） | `assets/source-webm/<分类>/`，然后重跑 `pipeline.py` |
| 新增固件模块 | `firmware/include/xxx.h` + `firmware/src/xxx.cpp` |
| 改引脚/分辨率/帧率 | `firmware/include/config.h` |
| 改转码参数（分辨率/帧率/质量/背景色） | `tools/pipeline/pipeline.py` 顶部常量 |
| 改 Flash 里放哪几段 | `tools/pipeline/pick_flash.py` 的清单 |
| 新的设计结论/实测 | `docs/`，并在 `README.md` 链接 |
| 换 ffmpeg | `tools/ffmpeg/`，用 `download-ffmpeg.mjs` 重下即可 |

## 五、gitignore 策略

**不入库**（换了电脑跑脚本重新生成）：`*.petpack`、`*.webm`、`*.mp4`、`*.zip`、
`tools/ffmpeg/`（200MB）、`.pio/`、`build/`、`__pycache__/`。

**要入库**（小文本、含决策信息，丢了就找不回来）：
`assets/animations.json`、`assets/sdcard/index.json`、`firmware/data/packs/index.json`、
`docs/calibration.json`、所有源码与 md。

> 因此 clone 下来**没有素材**，必须跑一次 `tools/pipeline/pipeline.py`。
> 这是刻意的：77.5MB 产物进 git 会让仓库永久膨胀。

## 六、命名约定

- 目录与文件用**中文**，跟素材来源（dsh-pet 插件）保持一致，便于对照
- 代码标识符用**英文**（`petpack.h`、`PackHeader`），命名空间统一 `pet`
- 脚本里的路径**全部相对本脚本定位**，项目整目录搬家不用改任何代码
