## 一、项目是什么

**ESP32-S3 桌面宠物**：一块 2.0 寸 SPI 屏循环播放角色动画，外壳做成摆件。

- 硬件：ESP32-S3-WROOM-1 **N16R8**（16MB Flash + 8MB Octal PSRAM）+ 2.0 寸 ST7789（320×240 横屏）
- 串口：板载 **CH343** 外置 UART 桥（不是原生 USB-CDC），日志 115200 / 烧写 921600
- 存储：**SD 卡优先**（`STORAGE_BACKEND=1`），挂载失败自动回退 Flash LittleFS

**素材两条线，互相独立**：

| 线 | 内容 | 状态 |
|:---|:---|:---|
| 西米（原创单角色） | 106 段，已转 petpack 上屏 | ✅ 全链路跑通 |
| 11 个 AI 角色 | chatgpt/claude/deepseek/gemini/glm/grok/hunyuan/kimi/minimax/qwen/seed，各 27 段（18 基础 + 6 互动 + 3 喂食），共 **297 段** | 🔧 素材层完成，**未转 petpack** |

**核心链路**：

```
WebM(alpha) ──pipeline.py──▶ .petpack(JPEG 序列) ──▶ SD 卡 / LittleFS
                                                        │
                          core1: 读帧 → JPEGDEC 解码 → PSRAM 后缓冲
                                                        │ 双缓冲交换
                          core0: DMA pushImage @40MHz → ST7789
```

## 五、关键决策与理由（别轻易推翻）

### 1. 用 JPEG 序列，不用 H.264

ESP32-S3 **没有硬件视频解码**。软解 H.264 的 320×240 需要十几 ms 以上且占用大量 RAM；JPEGDEC 有 S3 SIMD 汇编优化，单帧约 29ms，可预测、可丢帧。

### 2. 素材与屏幕 1:1，放大在流水线完成（最重要）

**踩坑历史**：早期素材是 320×180，固件运行时放大到 320×240，试了 1.33 / 1.40 / 1.50 / 1.60 / 2.0 五档。

| 倍数 | 配置 | 实测 |
|:---|:---|:---|
| 1.33 | 4/3 | 人物明显偏小 |
| 1.50 | 3/2 | 人物完整、大小合适 |
| 2.00 | 2/1 | 切掉头发和脚 |

**结论**：运行时放大只是把已有像素复制/插值，**越拉越糊，且每帧多花 15ms**。

**现在的做法**：pipeline 从源画面 640×360 **居中裁 426×320**，再 lanczos 缩放到 320×240，全程用源视频真实像素。

```python
# tools/pipeline/pipeline.py
WIDTH, HEIGHT = 320, 240
CROP_W, CROP_H = 426, 320   # 改这里要同步改 config.h 的 kFrameW/kFrameH
```

### 3. 双缓冲 + 双核，把 sum 变 max

解码 29ms + 刷屏 30ms 串行 = 59ms。双缓冲让两者重叠，实测约 74ms/帧，稳定 13fps。

### 4. 解码必须输出大端（RGB565_BIG_ENDIAN）

`pushImage` 是 **DMA 直发内存字节**，不做转换；ST7789 的 SPI 按大端收。用小端的后果：**红显示成蓝、绿显示成红**，极易误判为"素材质量差"。

### 5. PSRAM cache 必须手动写回

ESP32 Arduino Core 2.x（IDF 4.4）**没有 `esp_cache.h`**，LovyanGFX 的 `dma_cache_sync` 是空实现。DMA 读到脏数据表现为**横纹/噪点**。用 ROM 的 `Cache_WriteBack_Addr()` 手动写回。

### 6. 分区表去掉 OTA slot

默认 16MB 分区给 spiffs 只有约 3.4MB，装不下素材。去掉 app1 后 storage 拿到 **11.93MB**。

```
app0,     app,  ota_0, 0x10000,  0x400000,   # 4MB
storage,  data, spiffs,0x410000, 0xBF0000,   # 11.93MB
```

### 7. 用 LittleFS 不用 SPIFFS

SPIFFS 是扁平结构、不支持真目录，而素材按分类分目录（`/packs/待机/xxx.petpack`）。

### 8. 存储后端抽象 + SD 回退

`config.h` 的 `Backend` 枚举 + `-DSTORAGE_BACKEND=0|1`，上层零改动切换。SD 挂载失败自动回退 Flash，
所以**烧了动画包的用户即使没插卡也能开机**。

### 9. SD 卡必须独立 SPI + 独立 5V（实测踩出来的）

- **独立 SPI3**：固件双线程并发（core1 读卡 + core0 DMA 刷屏），共用一条 SPI 会抢总线 → 随机花屏/读卡超时
- **VCC 必须独立 5V 且共地**：模块板载 AMS1117 压差约 1.1V，接 3.3V 输出只有 2.2V，卡欠压不启动
- **开发板 `5VIn` 不能用**：`in` 是外部输入脚，USB 供电时它没有输出
- FAT32 / ≤32GB，exFAT 直接 `SD.begin` 失败且报错不指向格式问题

### 10. 版本号由 release.py 生成（version.h）

不要在代码里手改版本号：`firmware/src/version.h` 由 `tools/release.py` 在构建前写入，
保证「烧进去的固件 = releases 里那个版本」。串口第一行 `[pet] boot vX.Y.Z (日期)` 就是版本凭据。

> ⚠️ **已知遗留**：`config.h::kFwVersion = "v1.1-fallback"` 是旧机制（开机屏显示），
> 与 version.h 的 `FW_VERSION` 未合并。统一方向是**全部读 version.h**，kFwVersion 待清理。

## 六、踩过的坑（现象 → 根因 → 解决）

| # | 现象 | 根因 | 解决 |
|--:|:---|:---|:---|
| 1 | 屏全黑，但串口正常 | 背光用 LovyanGFX `Light_PWM` 输出不了电平；且 GPIO13 是 SPI2 默认 MISO | 背光改裸 GPIO `pinMode + digitalWrite(HIGH)` |
| 2 | 黑白颠倒 | `cfg.invert = true` | 改 `false` |
| 3 | 红蓝互换 | `cfg.rgb_order = true` | 改 `false` |
| 4 | 颜色循环错位（红→蓝→绿） | 解码输出小端，DMA 直发被大端 SPI 读走 | `RGB565_BIG_ENDIAN` |
| 5 | 画面横纹 / 噪点 | PSRAM cache 未写回 | `Cache_WriteBack_Addr()` |
| 6 | 80MHz 黑屏 / 花屏 | 杜邦线撑不住 80MHz | 40MHz（20MHz 保底） |
| 7 | PSRAM 分配失败 | `memory_type = qio_qspi` 与 Octal PSRAM 不符 | 改 `qio_opi` |
| 8 | 画面模糊，放大越多越糊 | 运行时插值造不出细节 | 放大搬到 pipeline（决策 2） |
| 9 | pipeline 输出只剩左上角一块 | filter 顺序错 | 顺序必须 **crop → scale → overlay** |
| 10 | 局部转换把 106 段索引覆盖了 | 冒烟模式也写全量 `index.json` | `--limit/--only` 时改存 `docs/smoke_index.json` |
| 11 | `LittleFS.begin` 挂错分区 | 第 4 个参数是 **partitionLabel** 不是挂载点 | 用 `kFlashPartLabel = "storage"` |
| 12 | 文件永远打不开 | FS 层自动拼 mountpoint，代码又拼了一次 | 代码里只写 `/packs` |
| 13 | 播放直接失败 | `.petpack` 头 w/h 与 `kFrameW/H` 不匹配 | 转素材尺寸必须同步 `config.h` |
| 14 | 鼠标拖大的素材放不进 Flash | 320×240 比 320×180 体积 +79% | Flash 只放 8 段，全量走 SD |
| 15 | 想让某段循环、又想自动换段 | 素材包 `loop` 标志恒为 1 | `player::play(path, once=true)` 忽略包内标志 |
| 16 | SD 四线电平全 0，CMD0 = 0x00 | 模块 6 针针位反接，VCC 落到 SCK 上 | 用万用表确认针位，别信记忆里的顺序 |
| 17 | SD 四线全 1，CMD0 = 0xFF | VCC 接 3.3V 欠压（AMS1117 压差） | 独立 5V 供电 + 共地 |
| 18 | VCC 接开发板 `5VIn` 无输出 | `5VIn` 是输入脚，USB 供电时无电 | 外接充电头/充电宝，黑线接板子 GND |
| 19 | 日志永远打印 "MMC" | `SD.begin` 返回的是 **bool**，被当卡类型用（成功恒为 1） | 改 `SD.cardType()` 取真实类型 |
| 20 | 64GB 卡挂不上 | 出厂 exFAT，Arduino SD 库只认 FAT16/32 | 用 ≤32GB 卡或格式化成 FAT32 |
| 21 | 白色角色 + 白碗在缩略图里"消失" | 白对白在深色缩略图里互相抵消 | 判断喂食落点必须**放大抽帧**，不能看缩略图 |
| 22 | SD 卡 106 段全部识别，但只有前 32 段会被播到 | 洗牌队列是固定 `uint16_t s_order[32]`，超出部分被静默截断 | 改 `std::vector` 按扫到的段数动态分配 |

- **版本规则**：主版本=大功能/硬件变更，次版本=新功能，修订号=bug 修复
- **流程**：写 version.h → pio 编译 → esptool merge_bin（不填满 16MB，只到 app 段结束）→
  生成文档 → 追加 `releases/README.md` 索引 → git tag
- **bin 全部入库**：`*.bin` 全局忽略，`!releases/**/*.bin` 负向放行
- 版本重复 / 目录已存在 / tag 已存在都会被拒绝，防覆盖
- `--skip-build` 复用现存 `.pio` 产物（仅调试；此时不会重写 version.h）

## 十、给下一个 AI 的注意事项

1. **`config.h` 是唯一常量来源**，改引脚/尺寸/频率只动这里，但 **`pipeline.py` 的 `WIDTH/HEIGHT/CROP_*` 必须同步**，否则 `.petpack` 校验会拒绝加载。
2. **不要手改版本号**。发版走 `tools/release.py vX.Y.Z`，它会生成 `version.h`（串口日志用）。开机屏目前读的是 `config.h::kFwVersion`，两者待合并。
3. **不要重新引入运行时缩放**。觉得人物小就改 `pipeline.py` 的 `CROP_W/CROP_H` 重转素材。
4. **别用 `git add .`**。`*.petpack`、`*.webm`、`tools/ffmpeg/`、`firmware/.pio/` 已忽略，但 `firmware/data/packs/` 下误放的包会撑爆仓库；`releases/**/*.bin` 是**故意入库**的。
5. **测试前先看串口**：`[pet] boot <版本>`、`[pet] backend = …`、`[pet] 扫到 N 段`、`[animator] 切换 → …`、`[pet] 已刷 N 帧，丢帧 M` 能直接定位问题层次。
6. **SD 卡相关改动要同时验证两条路径**：插卡（SD）与拔卡（回退 Flash），后者靠 `firmware/data/` 的 8 段预置。
7. **当前播放行为**：全部段洗牌轮播（Fisher-Yates），一轮内不重复。洗牌队列是 `std::vector<uint16_t>`，按扫到的段数动态分配，SD 卡 106 段全覆盖；之后做分池抽签直接在这个基础上改。
8. **`docs/阶段1-硬件接线教程.md` 里标 ⚠️ 的仍是未上机内容**（主要是 TTP223），不要当已验证事实引用。
9. **多角色素材别碰 `assets/<角色>/` 下的 webm**，它们是 gitignore 的源；要重新生成就重跑 `build_character_preview.py` / `build_interactions.py`。
