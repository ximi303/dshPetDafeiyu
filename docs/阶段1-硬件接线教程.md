# 阶段 1 硬件接线教程

> **本文档只记录实机上电验证通过的方案。**
> 未上机验证的内容一律标注 ⚠️，与已验证部分严格区分，避免照抄出问题。

硬件平台：ESP32-S3-WROOM-1 N16R8（16MB Flash + 8MB Octal PSRAM）
显示：2.0 寸 ST7789 SPI 屏，物理 240×320，横屏使用 320×240
当前固件版本：`v0.9-shuffle`（开机左上角会显示，用来确认烧的是哪一版）

## 二、供电

| 项目 | 做法 |
|:---|:---|
| 主控供电 | USB Type-C 5V 直供 |
| 屏幕供电 | 从开发板 **3V3** 引脚取电，不要接 5V |
| 背光 | 屏幕 BLK 接 GPIO13，由固件拉高点亮 |

**电流估算**：屏幕背光约 40~60mA，主控 + PSRAM 约 80~120mA，峰值 200mA 以内，USB 口完全够用。

> 后续接 TF 卡后峰值会上升约 200mA（写卡瞬间），USB 供电仍然够；若改用电池供电需重新核算。

## 三、屏幕接线（✅ 已验证）

### 接线表

| 屏幕引脚 | 接到 ESP32-S3 | 说明 |
|:---|:---|:---|
| **VCC** | 3V3 | 不要接 5V |
| **GND** | GND | 必须共地 |
| **SCL**（部分板标 SCK） | **GPIO 12** | SPI 时钟 |
| **SDA**（部分板标 MOSI） | **GPIO 11** | SPI 数据输出 |
| **RES**（部分板标 RST） | **GPIO 8** | 复位，低电平有效 |
| **DC** | **GPIO 10** | 数据/命令选择 |
| **CS** | **GPIO 9** | 片选 |
| **BLK**（部分板标 BL） | **GPIO 13** | 背光，**高电平点亮** |
| MISO | 不接 | 本方案只写屏不读屏 |

### 引脚命名对照

不同厂家的丝印不一样，认准功能即可：

| 功能 | 常见丝印 |
|:---|:---|
| 时钟 | SCL / SCK / CLK |
| 数据输入 | SDA / MOSI / DIN |
| 复位 | RES / RST |
| 数据/命令 | DC / RS / A0 |
| 片选 | CS / SS |
| 背光 | BLK / BL / LED |

### 三个接线坑（都踩过）

**① GPIO13 是 SPI2 的默认 MISO 引脚**

LovyanGFX 初始化总线时会配置默认引脚，如果只用 `Light_PWM` 类控制背光，实测**输出不了电平**（BL 直连 3V3 能亮，说明屏是高电平点亮）。

**解决**：背光不挂 LovyanGFX 的 Light 类，改用裸 GPIO：

```cpp
pinMode(kPinBl, OUTPUT);
digitalWrite(kPinBl, HIGH);
```

**② 不要给屏接 5V**

屏板载 LDO 的耐压有限，且 5V 供电会让逻辑电平变成 5V，超 S3 的 3.3V 绝对最大值。

**③ 杜邦线长度**

40MHz 下已验证稳定，但线长超过 20cm 或走线凌乱时可能出现雪花。若出现，先降到 20MHz 验证，再逐级上调。

### SPI 频率实测记录

| 频率 | 结果 |
|:---|:---|
| 80 MHz | ❌ 黑屏 / 花屏（杜邦线撑不住） |
| 40 MHz | ✅ 稳定，320×240 全屏刷屏约 30ms |
| 20 MHz | ✅ 稳定，刷屏约 61ms |

**当前用 40MHz**，是 12fps 帧预算（83ms）下的必要选择。

### 自检方法

`display.cpp` 的 `display::begin()` 里有两块用 `#if 0` 关闭的调试代码，把 `0` 改成 `1` 重新编译即可开启：

| 调试块 | 验证内容 | 期望现象 |
|:---|:---|:---|
| A. `fillScreen` 六色 | 背光、SPI 通路、invert / rgb_order | 白→黑→红→绿→蓝→黑 |
| B. 纯色 `pushImage` | PSRAM 双缓冲、cache 写回、DMA 全链路 | 红→绿→蓝 三块均匀纯色 |

判读方法：

- 黑白颠倒 → `cfg.invert` 配反
- 红蓝互换 → `cfg.rgb_order` 配反
- 全程黑 → SPI 数据没通（查 MOSI/SCLK/DC/CS，或把频率降到 20MHz）
- 有横纹 / 噪点 → PSRAM cache 未写回，或 SPI 太快

## 五、TF 卡接线（✅ 已验证）

> **2026-11 实测通过**：SDHC 16GB 卡挂载成功、106 段全部识别、连续播放丢帧 0.8%。
> 本章按实际验证结果记录，踩过的坑保留在文末。

### 模块特性

照片对应的是 **欣薇（Xnvi）Micro SD 模块**，V717 同类：

- 板载 **AMS1117-3.3** 线性稳压器（丝印 `1117C 33 D550`）
- R1/R2/R3 上拉电阻 + C1~C4 滤波电容
- 板载电平转换电路：卡侧 3.3V，控制侧 3.3V/5V 均可
- 供电 **4.5 ~ 5.5V**
- 支持 Micro SD（≤2G）/ Micro SDHC（≤32G）
- 6 针 SPI 接口，厂家文档标明的针位顺序是：**GND / VCC / MISO / MOSI / SCK / CS**

> ⚠️ **这一条曾写错，导致整条 SPI 反接。**
> 最初按照片目测记成 `CS / SCK / MOSI / MISO / VCC / GND`，正好与实物完全相反。
> 反接的后果不是"不工作"这么简单 —— 你以为接到 5V 的那根是 VCC，实际是 **SCK**，
> 5V 直接灌进信号脚。**换模块或重接线时，第一件事是用万用表确认针位，别信任何记忆里的顺序。**

### 先确认针位顺序（必做，2 分钟）

**方法一：万用表通断档（最可靠）**

断电状态下测：

| 要确认的针 | 判据 |
|:---|:---|
| GND | 与卡座金属外壳 / 板上大面积覆铜**导通** |
| VCC | 与 AMS1117 的**输入端**导通（3 脚封装，靠 `VIN` 丝印那侧） |
| 3.3V 输出 | 与卡座 VDD 触片导通（用来反查 VCC 是否接对） |

**方法二：看丝印**

排针旁有 6 个白色丝印字母，手机微距拍照放大逐个读。**注意方向** —— 是从靠近卡座那端开始，还是相反。

**方法三：看走线**

`GND` 连接的铺铜面积最大；`CS` 通常直连卡座旁一个孤立焊盘。

### 三条硬约束

**① VCC 必须接 5V，不能接 3.3V**

AMS1117 的压差约 1.1V：

```
VCC 接 3.3V  →  输出仅约 2.2V  →  SD 卡不工作（或时好时坏）
VCC 接 5V    →  输出稳定 3.3V  →  正常
```

这是该模块最常见的翻车点。

**② 信号线是 3.3V 电平**

板上已降压并做过电平转换，CS/SCK/MOSI/MISO 均为 3.3V 逻辑，直连 S3 无需额外转换。

**③ 卡必须是 FAT32 且 ≤32GB**

### 推荐接线（独立 SPI 总线）

| 模块丝印 | 针位 | 接到 ESP32-S3 | 说明 |
|:---|--:|:---|:---|
| **GND** | 1 | **GND** | 必须共地 |
| **VCC** | 2 | **独立 5V 电源** | ⚠️ 板载 5VIn 实测无输出（见下方"供电坑"）；须外部 5V 且共地 |
| **MISO** | 3 | **GPIO 16** | 卡 → 主板 |
| **MOSI** | 4 | **GPIO 15** | 主板 → 卡 |
| **SCK** | 5 | **GPIO 14** | 时钟 |
| **CS** | 6 | **GPIO 5** | `config.h` 的 `kSdCsPin` |

**接的时候对着模块上的丝印字母接，不要按针位序号接** —— 序号只用于对照，丝印才是唯一可信的锚点。

接错一个典型后果（实测过一次）：

```
模块针位反接 → VCC 落到 SCK 上、GND 落到 CS 上
            → 模块根本没有供电，3.3V 轨为 0V
            → 板上 R1/R2/R3 上拉电阻把四根信号线全拉到 GND
            → 固件读到 SCK/MOSI/MISO/CS 静态电平全为 0
            → SD.begin 报 GO_IDLE_STATE failed（卡没有任何响应）
```

这个现象很容易被误判成"卡坏了"或"模块坏了"，实际只是针位顺序反了。

### 供电是第二个坑（实测）

这块 ESP32-S3 双 USB 板的 `5VIn` 引脚**不能给 SD 模块供电**。三种供电状态的实测对比：

| 供电方式 | 四线静态电平 | CMD0 响应 | 结果 |
|:---|:--:|:--:|:---|
| VCC 接 `5VIn`（USB 供电） | `0 0 0 0` | `0x00` | 5VIn 无输出，模块无电 |
| VCC 接 `3V3` | `1 1 1 1` | `0xFF` | 上拉正常，但 AMS1117 输出仅约 2.2V，卡欠压不启动 |
| **VCC 接独立 5V（共地）** | `1 1 1 1` | **`0x01`** | **挂载成功，106 段全部识别** |

为什么 `5VIn` 不行：丝印里的 `in` 表示这是**外部电源输入**脚，与 USB VBUS 之间隔着
二极管，单向导通 —— 只能往里灌电，USB 供电时它自己没有输出。
就算有的板子能量到 4.3V 左右（二极管压降后），也差 AMS1117 那口 1.1V 压差。

**独立 5V 的取法**：手机充电头或充电宝 + 剪开的旧 USB 线（红 = 5V，黑 = GND，
白绿剪掉）。**黑线必须同时接到开发板 GND** —— 两个电源必须共地，
否则 SPI 信号没有共同参考电平。

### 排障速查（本章两坑总结）

| 固件读到的现象 | 根因 |
|:---|:---|
| 四线电平全 `0`，CMD0 = `0x00` | 模块没供电（针位反接 / 5V 没接上） |
| 四线电平全 `1`，CMD0 = `0xFF` | 有电但卡欠压（AMS1117 输入不足 4.4V），或卡/卡座问题 |
| 四线电平全 `1`，CMD0 = `0x01` | 正常，应能挂载并列出素材 |

固件 `storage.cpp` 在挂载失败时会自动打印四线电平和裸 SPI CMD0 探测结果，
按上表对号入座即可。

### 为什么必须用独立 SPI3，而不是和屏共用 SPI2

当前固件是**双线程并发**：

```
core 1  player::tick()  →  从存储读 JPEG（走 SPI）
core 0  displayTask     →  DMA 刷屏（走 SPI2）
```

如果 SD 也挂在 SPI2，会出现「DMA 正在推屏、SD 同时读下一帧」的总线争用，表现为**随机花屏、横纹、读卡超时**，且极难定位。

ESP32-S3 有两条独立 SPI 控制器：

| 控制器 | 分配给 |
|:---|:---|
| SPI2 (FSPI) | LCD 独占 |
| SPI3 (HSPI) | SD 独占 |

### 代码改动清单（实施时参考）

| 文件 | 改动 |
|:---|:---|
| `config.h` | 加 `kSdSckPin=14` / `kSdMosiPin=15` / `kSdMisoPin=16` |
| `storage.cpp` | 建 `SPIClass s_sdSpi(HSPI)`，显式 `begin(sck, miso, mosi, cs)`，`SD.begin` 传该实例 |
| `platformio.ini` | `-DSTORAGE_BACKEND=0` → `=1` |
| `main.cpp` | 无需改动（存储层已抽象） |

> **注意**：ESP32 老款 HSPI 的默认引脚是 12/13/14/15，其中 **13 现在是背光**。所以必须显式指定引脚，不能依赖默认值。

### 验证顺序（建议）

1. **只验接线**：挂载 SD、打印卡容量与根目录，不碰动画
2. **切后端**：`STORAGE_BACKEND=1`，卡里放少量包，确认播放无花屏
3. **全量上卡**：106 段约 138MB（8GB 卡占 1.7%）
4. **长时运行**：10 分钟以上，观察丢帧数与读卡超时

### 回退方式

`STORAGE_BACKEND` 改回 `0` 即可，Flash 里的素材不受影响。

## 八、排障速查表

| 现象 | 根因 | 解决 |
|:---|:---|:---|
| 全黑，串口正常 | 背光未点亮 | BL 接 GPIO13，固件 `pinMode+digitalWrite(HIGH)` |
| 全黑，串口无输出 | 供电 / 烧录失败 | 查 USB 线是否数据线、boot 模式 |
| 黑白颠倒 | `invert` 配反 | `cfg.invert = false` |
| 红蓝互换 | `rgb_order` 配反 | `cfg.rgb_order = false` |
| 颜色循环错位（红变蓝绿变红） | 字节序错 | 解码输出 `RGB565_BIG_ENDIAN` |
| 画面有横纹 / 噪点 | PSRAM cache 未写回 | `Cache_WriteBack_Addr()` 手动写回 |
| 花屏 / 雪花 | SPI 太快 | 40MHz → 20MHz |
| 画面模糊 | 素材分辨率不足被放大 | 素材侧裁切放大，固件不做缩放 |
| 动画卡顿 | 帧预算超支 | 查解码耗时与刷屏耗时，确认 DMA 已开 |
| `SD.begin` 失败 | VCC 接了 3.3V / 卡是 exFAT | VCC 接 5V；格式化为 FAT32 |
